# QQ 群机器人

机器人沿用现有官方 QQ API 接入、AppID/AppSecret 和 `groupOpenIDs`，支持房间列表与开局通知。

## 每日配役

启用 `qqbot.enable` 并配置目标群后，默认每天北京时间 **10:00** 推送一份配置：

- 配置总人数随机选择：**12–18 人合计 70%**、**19–30 人合计 30%**，每个区间内部等概率。不另加替身名额；指令指定人数时直接使用输入值。
- 使用黑暗火锅 **高安全性（high）** 原算法，默认公开职业、非化学、非两阵营、非败北村。
- 真实 `Human` 村人占比在 **10%–40%**：从 `ceil(人数×10%)` 到 `floor(人数×40%)` 的整数人数中均匀随机。例如 12 人配置为 2–4 村人，30 人为 3–12 村人；思念系等显示为村人的职业不计入。
- 占卜师 / SP占卜师 / 无谋占卜师三种职业中**至少存在一名**，保底职业等概率选择；原算法仍可再生成占卜职业。
- 村人与保底占卜职业先预留名额，其余名额按原高安全性算法生成，不在事后替换职业。新约束只作用于独立推荐（每日推送及使绊子指令），不改变实际游戏开局规则。
- 展示每个真实职业的名称及人数，不创建房间、不改变对局。
- 一次推送的所有目标群收到同一份名单。

无需新增依赖或配置字段即可启用。若需单独关闭每日推送，在现有本地配置的 `qqbot` 下添加：

```coffee
    dailyCasting: false
```

每日推送和指令回复均使用同一个单行模板，不添加日期标题：

```text
13人 - 使绊子 / 村人: 4 占卜师: 1 灵能者: 1 猎人: 1 共有者: 2 人狼: 2 低语狂人: 1 妖狐: 1
```

目标群复用 `groupOpenIDs`，兼容旧的单群 `groupOpenID`。每日消息使用纯文本，不改变既有开局播报的 Markdown 或按钮。

调度固定 `Asia/Shanghai`，不受服务器时区影响，启动时不补发错过的推送。MongoDB 自动使用新集合 `qqbot_daily_castings`，按北京时间日期和群 OpenID 记录发送状态；其 `_id` 唯一索引防止同一天重复发送，也适用于多实例。无需手动建表或索引。

为避免群消息重复，发送失败或进程在发送途中退出不会自动重试当天该群的推送。可在服务日志及集合中检查 `sending`、`sent`、`failed` 状态。服务必须在 10:00 运行且数据库可用。

## 使绊子指令

群里发送：

- `@机器人 /使绊子`：随机选择 12–30 人，返回高安全性火锅名单。
- `@机器人 /使绊子 18`：指定总人数，允许 12–30 的整数。
- 也兼容 `@机器人 使绊子` 和全角斜线 `／使绊子`。

只回复触发指令的群，携带原消息的 `msg_id`，不会群发到其他目标群。对重复推送的指令事件在五分钟内去重；不识别为配役指令的 @ 消息仍按原逻辑返回房间列表。配役回复使用纯文本，不附带房间列表按钮。

**以上手动 @ 用法只需部署代码，无需额外配置。** 若希望在 QQ 输入框输入 `/` 时出现“使绊子”入口，还需在[机器人管理端](https://q.qq.com/)的指令配置中添加：

- 指令名：`使绊子`
- 指令介绍：`生成高安全性火锅配置`
- 使用场景：QQ群
- 使用权限：所有人（或按群需求设定）

入口配置遵循管理端实际提供的发布流程。后端仍接收 `GROUP_AT_MESSAGE_CREATE`，无需增加 Intent 或新建 Webhook。普通群文本中的 `/使绊子` 若未通过面板或 @ 发给机器人，当前接入不会监听到。

当前实现不调用指令面板管理 API，不会覆盖机器人的已有面板配置。

## 验证

```sh
node tests/random-casting.js
node tests/qqbot-daily-casting.js
node tests/qqbot.js
```

测试在本地生成配置并模拟数据库和 QQ 发送，不会连接 QQ 或发送群消息。算法抽取时另以 720 组固定随机序列对照原开局实现，涵盖原有安全等级、普通/手调/简易火锅，结果一致。
